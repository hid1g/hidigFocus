# Ускорение hidigFocus — 26 сентября 2026

## Что найдено и изменено

1. `AppStore.task(id:)` выполнял линейный поиск с копированием элементов большой модели. Добавлен индекс ID → позиция; позиция проверяется перед чтением, чтобы добавление/удаление/импорт/отмена не возвращали чужую задачу. Поля читаются из актуального массива, не из устаревшей копии.
2. `PlannerCalendar.time` создавал DateFormatter при каждом вызове. Форматтеры теперь переиспользуются отдельно в каждом потоке; ключ включает часовой пояс и формат времени, число записей ограничено.
3. Скрытые посещённые разделы оставались в дереве SwiftUI и наблюдали общий AppStore. Теперь в дереве находится открытый раздел. Поиск, фильтры, дата, режим, положение календаря/списка, выбранная запись журнала и неделя привычек хранятся вне исчезающих экранов. Полное сохранение курсора/каждого локального состояния остальных экранов не подтверждено.
4. Счётчики бокового списка раньше вызывали фильтрацию и сортировку всех задач для каждого списка. Теперь считаются одним проходом и переиспользуются до изменения задач, суток или видимости выполненных. Название и цвет списка в строках читаются без повторной сортировки списков.
5. Ввод поиска локализован в отдельном поле. Общая фильтрация запускается через 150 мс после прекращения ввода; сам текст вводится сразу.
6. Согласование импорта TickTick находило задачу линейным поиском для каждой записи. Добавлен индекс источника, обновляемый при добавлении задач. Сохранены правила согласования локальных правок.
7. Исправлен конфликт флага синхронизации: refresh устанавливал флаг, затем вызывал публичный synchronizeTasks, который возвращался из-за того же флага. Внешние методы защищены от перекрытия; общий внутренний метод выполняет синхронизацию под уже захваченным флагом. Реальный импорт в этой приёмке не запускался вручную.
8. Календарь создаёт тяжёлые карточки для видимого периода и одного соседнего дня с каждой стороны; дальние колонки заменены пустыми рамками. Во время перехода сохраняются оба периода, а источник активного переноса удерживается. Размер полосы остаётся прежним.
9. `build-app.sh` по умолчанию собирает release. Ранее пользователю выдавалась debug-сборка. Для диагностики debug можно явно выбрать переменной HIDIGFOCUS_BUILD_CONFIGURATION.

## Измерения

Одинаковый XCTest-сценарий на одном Mac, 10 000 синтетических задач, debug до/после. Форматирование первых 1 000 подписей и запрос последних 1 000 задач по ID. По одному зафиксированному запуску; это не p95 и не измерение кадров.

| Операция | До, мс | После, мс |
|---|---:|---:|
| 1 000 подписей дат/времени | 113.921 | 4.843 |
| 1 000 запросов ID среди 10 000 задач | 3035.628 | 1.814 |

Время подтверждает ускорение этих операций. Оно не означает ускорения всего приложения в таком же отношении.

Трёхсекундный sample запущенного приложения до исправлений: `/tmp/hidigfocus-performance-before.sample`. В этой записи основной поток ожидал события; постоянная загрузка процессора в простое не подтверждена. Для задержек при взаимодействии нужна отдельная запись активного сценария.
