# Иконка после завершения приложения

## Причина

`NSApplication.applicationIconImage` и `dockTile.contentView` принадлежат работающему процессу. Сохранение выбранного цвета в UserDefaults само по себе не меняет иконку неработающего приложения. Встраивание выбранного цвета при сборке также не решает последующую смену цвета.

## Изменение

В приложение включён `HidigDockTilePlugin.docktileplugin`, объявленный через `NSDockTilePlugIn`. Он читает `appIconPreference` из домена `com.hidig.focus`, выбирает один из восьми встроенных PNG и обновляет NSDockTile. Смена цвета отправляет уведомление после сохранения настройки. При подключении новой плитки модуль самостоятельно читает последнюю настройку; уведомление не является единственным источником состояния. Неизвестный цвет возвращает оригинал. Токены, задачи и другие данные модулю не нужны.

Изображения создаются тем же рендерером, что и предпросмотр. Сборка больше не зависит от личной настройки цвета; в ресурсах подписаны все варианты. Подписанный bundle в процессе работы не изменяется.

Документация Apple: https://developer.apple.com/documentation/appkit/nsdocktileplugin

## Проверка 20 сентября 2026

- Сборка и строгая проверка подписи приложения/вложенного модуля проходят.
- 33 unit-теста проходят; live-import тест пропущен.
- Отдельный тестовый процесс загружает собранный плагин, получает текущую сохранённую иконку и сравнивает изображение с соответствующим ресурсом. Проверено также отключение/повторное подключение плитки.
- macOS показывает расширение «hidigFocus / Плитка панели Dock» включённым.
- Реальная загрузка модуля процессом Dock и вид иконки после выхода пока НЕ подтверждены, включая после перезапуска Dock. Изолированный тест не доказывает сквозной результат.
- Закреплённая запись hidigFocus в настройках Dock сохраняет `dock-extra = false`; у реально загруженного модуля другого приложения — `true`. Первым шагом требуется удалить старое закрепление и закрепить приложение заново. Перезапуск Dock сам по себе этот признак не обновил. UI-инструмент не получил окно Dock, поэтому повторное закрепление не выполнено.
- AMFI журнал содержит замечание к ad-hoc подписи модуля. На машине нет доступных valid codesigning identities. Это возможная причина, не установленная окончательно. Защита macOS не отключалась.

Для сборки с существующим сертификатом разработчика поддержана переменная `HIDIGFOCUS_SIGNING_IDENTITY`. Без неё используется прежняя ad-hoc подпись. После обновления закрепления требуется повторить проверку в реальном Dock: два разных цвета, полное завершение, повторный запуск, перезапуск Dock. Не считать задачу закрытой до этой проверки.

Изолированная проверка (не запускает hidigFocus, не изменяет его настройки):

```sh
xcrun clang -fobjc-arc -framework Cocoa scripts/check-dock-plugin.m -o /tmp/hidigfocus-check-dock-plugin
/tmp/hidigfocus-check-dock-plugin "$PWD/dist/hidigFocus.app/Contents/PlugIns/HidigDockTilePlugin.docktileplugin"
```
