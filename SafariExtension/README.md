# hidigFocus Safari Guard

Safari Web Extension получает тот же текущий список доменов из локального hidigFocus, что и расширение Chromium. Блокирует переходы на домены и их поддомены через declarativeNetRequest. При разрешённом доступе к домену показывает собственную страницу «Сайт заблокирован» без кнопки обхода; без разрешения сохраняет стандартную блокировку Safari. Существующие вкладки нужно перезагрузить; загруженная страница сама не закрывается.

Для создания содержащего приложения и Xcode-проекта установите полный Xcode и выполните из корня проекта:

```bash
./scripts/build-safari-extension.sh
```

Для установки отдельного контейнера:

```bash
./scripts/install-safari-extension.sh
```

Установщик заменяет только `/Applications/hidigFocus Safari.app`; прежнюю версию сохраняет в `SafariBuild/Backups/`. Основное приложение, задачи, привычки, настройки и расширение Chrome не меняются. `HIDIGFOCUS_SAFARI_SKIP_OPEN=1` позволяет установить без открытия контейнера.

После установки включите расширение в Safari: Настройки → Расширения → hidigFocus Safari Guard. Разрешите связь с `http://127.0.0.1:17321/`, если Safari запросит. В кнопке расширения можно обновить правила и увидеть фактическое количество redirect- и block-правил в Safari и время последнего обновления.

Кнопка «Включить страницу hidigFocus» запрашивает доступ только к перечисленным текущим заблокированным доменам и их поддоменам по HTTP/HTTPS. Wildcard в `optional_host_permissions` лишь разрешает такие точечные запросы для новых доменов; расширение не запрашивает общее разрешение на все сайты. Для redirect нужны обе заявленные DNR-permission; `declarativeNetRequest` остаётся для обычного block без доступа к домену. При добавлении нового домена без выданного разрешения действует стандартная блокировка Safari, пока доступ не будет предоставлен.

При отзыве доступа к домену соответствующий redirect атомарно заменяется на block даже без связи с приложением. Собственная страница не содержит кнопок перехода назад, продолжения или отключения правил. Это убирает кнопку обхода со стандартной страницы ошибки Safari; пользователь по-прежнему может управлять расширением и его разрешениями в настройках браузера.

Без сертификата сборка подписывается ad hoc. Для неё в Safari требуется «Разрешить неподписанные расширения»; Apple сбрасывает это разрешение при выходе из Safari. Это тестовый режим, не постоянная установка. Для сборки с уже настроенным сертификатом:

```bash
HIDIGFOCUS_SAFARI_SIGNING_IDENTITY='Apple Development: …' \
HIDIGFOCUS_SAFARI_DEVELOPMENT_TEAM='…' \
./scripts/build-safari-extension.sh
```

Скрипт не создаёт сертификаты и не входит в учётную запись Apple. Настройка подписи выполняется отдельно через Xcode.

Правила обновляются при запуске расширения и по таймеру примерно каждые 30 секунд; Safari может задерживать фоновые таймеры. Запуск и кнопка «Обновить правила» повторно применяют правила в Safari даже при неизменном списке; таймер пропускает лишнюю перезапись. При недоступности приложения или некорректном ответе сохраняются последние применённые правила. Явный пустой список от приложения снимает блокировку. Popup показывает ошибку, если обновление не удалось. При первом запуске без связи с hidigFocus правил ещё нет. Наличие правил в popup подтверждает их сохранение в Safari, но фактическую блокировку проверяют переходом на сайт.

Проверка логики без изменения приложения или браузеров:

```bash
node --test Tests/SafariExtensionTests.cjs
```

Документация Apple: [установка и ограничения неподписанных расширений](https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension), [блокировка через declarativeNetRequest](https://developer.apple.com/documentation/safariservices/blocking-content-with-your-safari-web-extension).
